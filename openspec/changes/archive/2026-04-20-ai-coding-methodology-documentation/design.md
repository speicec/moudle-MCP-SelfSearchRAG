## Context

本项目已积累15+次OpenSpec变更迭代，形成了一套成熟的AI协作开发模式。但方法论仍停留在"隐性知识"状态，需要显性化文档。

### 现有实践基础
- 四阶段工作流：EXPLORE → PROPOSE → APPLY → ARCHIVE
- 三层文档体系：proposal/design/specs/tasks
- 决策文档化：Choice + Rationale + Alternatives
- 任务原子化：单文件单功能可验证

### 缺失部分
- 编码特质未系统化
- Agent.md模板未提炼
- 实例演示不完整
- 快速配置指南缺失

## Goals / Non-Goals

**Goals:**
- 创建完整方法论文档体系（7篇文档）
- 固化编码特质规范（测试先行、主动测试、遵循规范、诚实查询、谨慎重构）
- 提炼可复用的Agent.md模板
- 提供实例演示
- 确保方法论可独立使用（不依赖本项目）

**Non-Goals:**
- 不修改现有代码
- 不创建新的OpenSpec工具
- 不翻译成英文（保持中文为主）

## Decisions

### Decision 1: 文档结构设计

**选择**: 7篇文档，层次分明

**理由**:
- README作为入口
- 每个主题独立文档，便于引用
- Agent.md模板可独立复制使用

**文档层次**:
```
README.md          → 概述入口
workflow-phases.md → 流程详解
artifact-templates.md → 模板速查
decision-documentation.md → 决策方法
task-granularity.md → 任务技巧
coding-traits.md   → 编码特质（新增重点）
agent-template.md  → Agent模板（新增重点）
```

### Decision 2: 编码特质设计

**选择**: 5大特质，各有具体行为规范

**理由**:
- 这些特质在本项目中反复验证有效
- 每个特质需要具体的"怎么做"指导
- 需要与AI行为关联（Agent.md中固化）

**特质定义**:
| 特质 | 定义 | AI行为 |
|------|------|--------|
| 测试先行 | 先写测试再写功能 | 实施前检查测试 |
| 主动测试 | 完成后主动验证 | 标记[x]前运行测试 |
| 遵循规范 | 遵守项目规范 | 读CLAUDE.md/规范文档 |
| 诚实查询 | 不猜测，先查证 | 遇到不确定先grep/read |
| 谨慎重构 | 小步重构，不破坏 | 保持接口，逐步改 |

### Decision 3: Agent.md模板设计

**选择**: 可直接复制使用的完整模板

**理由**:
- 其他项目需要快速配置AI行为
- 模板应包含所有特质规范
- 使用YAML frontmatter便于Claude识别

**模板结构**:
```yaml
---
name: project-agent
description: 项目AI协作Agent
---

# 项目背景
# 编码特质
# 工作流程
# 文档规范
# 禁止行为
```

## Risks / Trade-offs

| Risk | Mitigation |
|------|------------|
| 文档太长难以阅读 | 分7篇独立文档，每篇聚焦单一主题 |
| 编码特质抽象难执行 | 每个特质配具体"AI行为"示例 |
| Agent模板不适配所有项目 | 提供定制指南，核心特质保留 |
| 方法论未实践验证 | 基于本项目600+任务验证，非空想 |
