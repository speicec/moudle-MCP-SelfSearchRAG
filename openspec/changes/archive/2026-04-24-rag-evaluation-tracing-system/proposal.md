# Proposal: RAG Evaluation & Tracing System

## Problem Statement

当前系统缺失两个关键能力：

1. **RAG 评价体系缺失**
   - 没有 Faithfulness / Context Relevance 等关键指标
   - 无法评估答案是否忠实于检索内容
   - 无法检测幻觉或无关上下文
   - 现有 recall-evaluation.test.ts 只是单元测试级别

2. **追踪数据无法持久化**
   - TraceVisualizer 数据只存在于内存
   - 无法查询历史追踪记录
   - 无法生成审计报告
   - 无法接入外部监控系统 (Jaeger/Grafana)

### 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 追踪持久化 | SQLite | 轻量、嵌入式、易查询、适合单节点 |
| 评估方法 | RAGAS + LLM-as-Judge | 无需人工标注，用现有 DeepSeek API |
| OpenTelemetry | 可选扩展 | 标准化但不强制，先满足核心需求 |
| 与现有系统集成 | Hooks + TraceContext | 最小改动，最大化复用 |

### 实现范围

**Phase 1 - 核心能力**
- TraceContext: 统一追踪上下文
- TraceStorage: SQLite 持久化
- EvaluationCollector: 收集评估数据
- EvaluationPipeline: RAGAS 评估
- MetricsAggregator: 整合指标

**Phase 2 - 可视化扩展**
- StatsDashboard 扩展: 评估分数面板
- TraceExplorer UI: 查询历史追踪
- EvaluationTrendChart: 评估分数趋势

**Phase 3 - OpenTelemetry (可选)**
- TraceExporter: OTLP span 导出
- 外部系统集成: Jaeger / Grafana Tempo

## Success Criteria

| 指标 | 目标 |
|------|------|
| 追踪持久化可靠性 | 100% 追踪记录可查询 |
| 评估流水线延迟 | < 5s (异步评估) |
| Faithfulness 评估准确度 | 与人工评估相关性 > 0.8 |
| 系统改动最小化 | 不破坏现有 MedicalAgent 功能 |

## Dependencies

- 现有 TraceVisualizer (扩展而非替换)
- 现有 DeepSeek API (用于 LLM-as-Judge)
- 现有 StatsDashboard + WebSocket (整合指标)
- SQLite (内置，无需额外安装)

## Risks

| 风险 | 缓解措施 |
|------|----------|
| LLM-as-Judge 可能不稳定 | 多次评估取平均 + 阈值告警 |
| 评估增加延迟 | 异步评估，不阻塞主流程 |
| SQLite 单节点限制 | Phase 3 可迁移到 PostgreSQL |
